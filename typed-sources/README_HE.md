# קליטת מקורות מוקלדים

בתיקייה זו אין כרגע תוכן מקור מוקלד. לא נכללו מסמכי דוגמה בהתקנה.

כאשר יהיו מקורות מוכנים, יש לשים כאן קובצי JSON תקינים בפורמט הקיים `canonical-legislative-sources`, בגרסה `1`, ולבנות מחדש. ההפעלה היא:

```sh
python3 scripts/build_web.py
python3 scripts/build_android.py
```

הסכמה היא זו שבחוזה הקיים, SHA-256:
`3bc9cd62e1a34978192b9eca3b4daa3eb5db9a5a3ee070e32b821e439f4373f3`.

מתקבלים ומאומתים כל 41 טיפוסי הסכמה. קובצי ה־JSON המקוריים אינם משתנים; מהם נגזר אינדקס החיפוש, הכולל מזהי מסמכים ויחידות, שיוכים, סדר קטעי הטקסט, נתוני הצבעות עם הבחנה בין null ל־0 וכתובות המקור. האינדקס אינו עותק מלא של כל שדות המסמך. קלט לא תקין חוסם את הבנייה עם שגיאה. כפילות זהויות, הפניות שבורות או טיפוס לא מוכר אינם מושמטים בשקט.

המסלול מקבל JSON חסר קוד בלבד. מודולי מקור מסוג `SOURCE_DOCUMENT`/`LEGISLATIVE_SOURCES` או `canonical()` צריכים לעבור קודם תהליך יצוא מהימן במחולל המקורות; האפליקציה והבנאי שלה אינם מריצים מודולים אלה ואינם מבצעים OCR.

היישום משתמש במפרט המתוקן `LEGAL_HTML_GENERATOR_3.8.0_SOURCE_FIRST_SEARCH_SPEC_v002_HE.md`: חיפוש במוקלד, הקשר תוצאה ופתיחה ישירה של `source_url`. תצוגת תמליל חלופית וייצוא פרוטוקולים אינם חלק מתשתית זו. פרטי מסמך רשמי אינם מנוחשים, ואין המרה אוטומטית של `law_name` למזהה סעיף בחוק.

בממשק: ״מקורות״ ← ״חיפוש במקורות מוקלדים״. אפשר לסנן הצעות חוק, פרוטוקולי ועדה או פרוטוקולי מליאה, לחפש בהתאמה מדויקת או מנורמלת ולהעתיק ציטוט עם האסמכתה. התאמות מאותו מקור מקובצות לכרטיס אחד. כתובת מקור חיצונית מקבלת תווית ניטרלית. אין כאן חיפוש מקורב.

האינדקס נוצר ב־`dist/typed-index.js` ונטען רק בפתיחת חיפוש המקורות. הוא נארז גם ב־APK ובמטמון גרסת הרשת. מסמכי DOC/PDF החיצוניים עצמם אינם מועתקים למכשיר. דוח קליטה, גיבובים ואבחון קישורים נכתב ב־`evidence/typed-source-build.json`.

מגבלות: עד 64 MiB לקובץ JSON, ועד 128 MiB במצטבר. קליטה נעשית בזמן בניית חבילת האפליקציה; ייבוא קבצים מתוך מסך הטלפון אינו ממומש בגרסה זו. אימות מבני אינו אישור לנאמנות משפטית. בדיקות התשתית משתמשות בדוגמאות סינתטיות בלבד, מפני שעדיין לא נמסר חומר מוקלד למשימה זו.
